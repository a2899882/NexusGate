# 安全模型

## 信任边界

- 控制面管理员是高权限主体，可以查看客户链接并下发配置。
- Agent 拥有其绑定服务器的配置权限，但不能领取其他服务器任务。
- Xray-core 独立运行；控制面不承载客户数据流量。
- 服务器 root 用户仍可读取本机凭据和流量日志，这是自托管系统无法消除的权限边界。

## 已实现控制

- 管理密码和 Agent Key 只保存 scrypt 哈希。
- 注册令牌为高熵随机值、单次使用、30 分钟到期。
- 管理 Cookie 使用 HttpOnly、SameSite=Strict、Secure。
- 状态变更 API 校验 CSRF Token。
- 登录失败按来源地址限速。
- Reality 私钥在 Agent 本机生成，不回传控制面。
- Agent 配置采用“候选配置校验 → 原子切换 → 失败回滚”。
- systemd 控制面启用 `NoNewPrivileges`、`ProtectSystem=strict` 和最小可写目录。
- 日志和已完成任务按保留期自动清理。

## 当前限制

- 客户协议凭据和待执行配置任务保存在权限为 `0600` 的控制面数据文件中，但 `v0.1` 尚未做字段级静态加密。备份同样包含这些凭据。
- 并发 IP 依赖 Xray 访问日志。修改日志格式、关闭访问日志或客户端经过同一 NAT 会影响结果。
- “设备数”不能从通用代理协议可靠推断；当前只保存策略值，等待一设备一凭据功能后强制执行。
- Agent 到控制面依赖公开 CA 的 HTTPS 校验，尚未增加双向 TLS。
- Xray Release 下载目前依赖 GitHub HTTPS，后续会增加强制校验和验证。

## 部署建议

- 控制面只允许 HTTPS，域名开启 HSTS。
- 使用独立管理域名，不与订阅或客户流量共用。
- 缩小服务器端口池，并仅在云安全组/防火墙中放行实际需要的 TCP/UDP 范围。
- 定期离线保存 `ng backup` 生成的文件，并对备份再次加密。
- 不要在聊天、工单或公开仓库中粘贴注册令牌、Agent Key、备份或客户链接。
- 首次上线前在测试链路验证 Xray 版本、Reality SNI、UDP 和回滚行为。
